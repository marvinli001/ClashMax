# ClashMax 原生 UI 焕新方案

日期：2026-11-07。状态：设计提案，尚未实施或完成视觉验收。

设计基于 ClashMax `3fab3fe` 的现有页面与交互，以及用户认可的 Kaset 参考。方向是 **Apple 原生 Liquid Glass + 现有 Pow + SwiftUIX 的 macOS 控件补充**。保留 macOS 15+，在 macOS 26+ 使用原生玻璃。

## 1. 最终体验

ClashMax 应像一款精致的 Mac 网络工作台：导航与操作轻盈通透，数据清楚稳定，日常操作短而直接。Kaset 提供窗口层次、通透侧栏和悬浮控件的参考；ClashMax 保留自己的电源符号、蓝色强调色和网络工具的信息密度。

最明显的五个变化：

1. 主窗口统一为系统工具栏、分组侧栏、紧凑状态行、内容工作区和按需详情。
2. 首页以当前出口、当前节点和流量为中心；启动前后保留可辨认的布局，减少整页跳变。
3. 节点、配置、连接、规则形成统一的选择、搜索、详情与操作语言。
4. 设置从一张长表单变为有分类、可搜索的原生设置工作区。
5. 菜单栏成为 320 pt 的精简控制中心，与主窗口共享状态和反馈。

## 2. 现状依据与必须保留的行为

| 当前实现 | 焕新判断 |
| --- | --- |
| `ContentView` 已使用 `NavigationSplitView`；工具栏放全局运行模式与启停 | 保留全局操作位置。页面操作继续在页面内，避免两个分段选择器混在一起 |
| `AdaptivePage` 已将页面标题交给窗口，使用独立页面操作行 | 演进现有容器，不再额外绘制大标题 |
| `AppSection` 有首页、状态、配置、代理、连接、路由、规则、日志、设置九个入口 | 全部保留，调整分组和视觉层级 |
| 首页分为 `LaunchDashboardView` 和 `RunningDashboardView` | 让两种状态共享内容骨架，保留状态判断与恢复操作 |
| 代理已有组列表、节点列表、浏览选中、双击/Return 启用、离线选择和后台搜索流水线 | 这些行为是基础；焕新不能重新引入主线程解析、测速抖动或选中即启用 |
| 配置已有原生表格、详情、编辑、导入与预检 | 保留全部入口以及“选中”和“设为当前”的区别 |
| 连接详情宽屏在右侧，窄屏堆在表格下方 | 提议窄屏改为按需 Sheet，增加表格可用高度；这是需要更新布局测试的明确行为变更 |
| 状态页已有按问题展开的诊断与恢复 | 保持诊断职责，首页只显示需要注意的摘要 |
| 菜单栏已为系统 `MenuBarExtra(.window)`，宽 320 pt | 保留系统表面和宽度，不重建第二层面板 |
| 已有 Pow、Shimmer、KeyboardShortcuts；已有诊断报告 `NSTextView` 桥接 | 优先复用；诊断长文本已有性能处理，不为引入 SwiftUIX 而替换 |

历史 `UI_LIQUID_GLASS_SWIFT6_AUDIT.md` 是归档，不是当前待修列表。其中“内容卡片不用玻璃”的已定选择继续保留；当时“不改变页面结构”的限制针对那次表面修复，本提案按本次全套焕新的请求重新设计布局。

本方案不扩充遥测、账号、订阅分析或网络能力。已有附属功能保留入口；界面调整不改变原始 YAML、运行时生成、控制器鉴权、Helper/NE 权限边界。

## 3. 窗口与信息架构

### 3.1 主窗口

继续使用默认 **1180 × 760 pt**、最小 **980 × 660 pt**，先保证已有可用尺寸。侧栏建议宽 200–240 pt，可由系统折叠与调整；页面内边距沿用现有窄屏 14、常规 18 pt 起步。

```text
┌─────────────────────────────────────────────────────────────────────┐
│ ● ● ●  侧栏  代理             [搜索…]      [规则 全局 直连] [停止]     │
├───────────────┬─────────────────────────────────────────────────────┤
│ 日常          │ 运行中 · 配置示例 · TUN 已接管                        │
│   首页        ├─────────────────────────────────────────────────────┤
│   配置        │ 页面操作                         [测速] [排序] [更多] │
│   代理        ├──────────────┬──────────────────────────────────────┤
│               │ 代理组       │ 节点                  延迟    当前     │
│ 观察          │ 自动选择     │ 节点 A                42 ms    ✓      │
│   连接        │ 流媒体       │ 节点 B                68 ms           │
│   规则        │ 开发         │ 节点 C                超时            │
│   日志        │              │                                      │
│               │              ├──────────────────────────────────────┤
│ 管理          │              │ 已选节点 B       [详情] [测速] [使用]  │
│   路由        ├──────────────┴──────────────────────────────────────┤
│   状态        │ 3 个代理组 · 128 个节点                               │
│   设置        │                                                     │
└───────────────┴─────────────────────────────────────────────────────┘
```

示意数据全部为虚构；此图表达布局，不代表已渲染的原生玻璃效果。

- **窗口工具栏**：系统标题、可用时的页面搜索、现有运行模式与启停。正常停止使用中性样式，不把运行中的整个界面染红。拥挤时模式收为菜单，保留标题与主动作。
- **侧栏**：原生 `List(selection:)`，用三组组织九个入口；SF Symbols 统一尺寸，选中效果交给系统。只有真实问题才给“状态”增加提示，保留 VoiceOver 文本。
- **状态行**：继续由同一运行状态产生，仅显示当前事实；正常时一行，异常时允许换行并有明确恢复入口。不要在 Toast、状态行、首页重复同一错误。
- **页面操作行**：搜索外的筛选、排序、导入、测速等；没有操作就不占一行。低频动作放“更多”，高频操作保持可见。
- **详情**：宽度足够时用系统 `.inspector`，不足时显式选择 Sheet；不假定 macOS 会随窗口宽度自动变成 compact size class。
- **页脚**：小号、低强调度显示筛选结果与总数；不再用卡片包起来。

### 3.2 自适应规则

断点根据扣除全局侧栏后的**页面可用宽度**计算，不能直接使用显示器或整窗宽度。

| 场景 | 处理 |
| --- | --- |
| 首页可用宽度 ≥ 800 pt | 节点/出口、流量/代理组按约 3:2 分栏 |
| 首页可用宽度 < 800 pt | 单列；主动作和当前节点先出现，其余自然滚动 |
| 配置详情 | 主表至少 480 pt、检查器 280–320 pt，能同时容纳才并排 |
| 连接详情 | 主表至少 660 pt、检查器 300–340 pt；不足时用 Sheet，详情仍可打开 |
| 代理工作区 | 组列 200–224 pt，节点区至少 440 pt；不足时组选择折为菜单；节点详情默认紧凑底栏，更多字段再展开 |
| 路由工作区 | 保留现有宽屏工具列、窄屏工具 Sheet；不增加第四列 |
| 短窗口和超长内容 | 列表/编辑器独立滚动，状态与操作可达；保留当前防溢出约束，禁止内容把标题栏或侧栏顶出窗口 |

这些尺寸是原型起点，最终以中文长标签、英文、系统字体和最小窗口实测调整，不硬编码系统控件自身高度。

## 4. 视觉规范与亮点组件

### 4.1 材质分层

| 层级 | 使用方式 |
| --- | --- |
| 窗口导航层 | 系统侧栏、工具栏、菜单、Sheet、Popover 自带材质；清除会遮挡系统效果的多余背景 |
| 自定义功能层 | 首页“当前节点”的紧凑快捷选择控件等少量可操作表面，在 26+ 使用原生玻璃；需要多个相邻自定义玻璃形状共同过渡时放进 `GlassEffectContainer` |
| 数据内容层 | 表格、日志、图表、设置表单、节点行用语义背景、选择高亮和分隔；保持文字与数字稳定 |

系统按钮优先使用系统样式；自定义玻璃控件使用公开 `glassEffect` / `glass` / `glassProminent` API。已有系统玻璃表面内部不再重复铺 material、光边和阴影。`backgroundExtensionEffect` 只在实际背景连续性有收益的区域试用，不为制造折射而增加装饰图片或动态渐变。

macOS 15 使用系统材质和标准按钮保持同一结构。Reduce Transparency 时自定义表面使用可读的实色语义背景；Increase Contrast、浅/深色和窗口失焦状态均纳入原型检查。

### 4.2 字体、色彩、间距

- 系统 SF 字体。正文以 13 pt、辅助 11–12 pt、区块标题 15–17 pt、关键流量数字 24–28 pt 为设计基准；实际使用语义字体。IP、端口、日志及 YAML 使用等宽字体；变化数字采用等宽数字。
- 沿用品牌蓝作为主要操作色。健康为绿、等待/注意为橙、失败为红；下载/上传图线用可分辨的蓝/青组合，并同时提供文字图例，不能只靠颜色识别。
- 间距采用 4/8/12/16/24 pt。沿用 `SurfaceRadius` 的 10/8/6 pt 层次；胶囊用于少量控制，表格数据不逐行胶囊化。
- 页面最多保留真正分组所需的浅表面。列表使用行和分隔，详情使用 `LabeledContent`，不继续堆叠“卡片里的卡片”。

### 4.3 三个识别度较高的组件

1. **当前节点快捷控件**：节点名、最近有效延迟、展开箭头组成紧凑玻璃控制。展开原生 Popover 后选择节点；当前使用状态和浏览选中状态明确区分。提交期间显示进行中，成功后勾号短促反馈。
2. **双向流量图**：扩大绘图区、减少外围装饰。两条曲线与固定位置的当前速率配合；保留现有历史数据范围。查看某一时刻时显示上下行数值，键盘与辅助技术可取得等价数据。先复用现有图表；若需新增交互，优先系统 Swift Charts。
3. **运行电源标识**：保留 `CoreVisualView` 的品牌识别，收敛为约 56–72 pt 的状态锚点。启动、就绪、失败通过符号和短时过渡表达；停止后仍显示可操作的配置和恢复信息。

## 5. 全部页面设计

### 首页

首屏回答“是否接管、使用哪个配置/节点、当前出口、流量是否变化”。顶部状态事实由全局状态行承担，页面不再复制一套大标题与运行摘要。

```text
┌───────────────────────────┬────────────────────────┐
│ 当前节点                  │ 公网出口               │
│ 组名 / 节点名 / 有效延迟   │ 地址 / 地区 / 检测结果  │
│ [切换节点] [测速]         │ [重新检测]             │
├───────────────────────────┼────────────────────────┤
│ ↓下载  ↑上传              │ 代理组                 │
│ 大幅流量趋势图            │ 当前节点 / 延迟 / 跳转  │
│ 当前值与总量分层展示       │ 仅展示必要摘要         │
└───────────────────────────┴────────────────────────┘
│ 仅在有问题时出现的注意事项与恢复动作               │
```

当前节点区顶部保留配置与接管方式的紧凑菜单；“规则/全局/直连”继续只属于窗口工具栏，区分运行模式与系统代理/TUN/NE 接管方式。停止时保留配置与节点选择位置，流量区明确显示“未运行”；初次使用显示导入配置和启动条件。真实异步数据读取才显示骨架。公网 IP 不等同于代理生效，检测结果继续使用现有证据判定；过期结果标明更新时间。刷新视觉不增加网络探测频率。

### 代理

- 保留“代理组 → 节点列表 → 已选节点操作”的工作流。组行展示组名、策略与当前节点，节点行对齐名称、协议、延迟、当前使用标记。
- 搜索继续使用现有 `.searchable` 和后台 `ProxySearchCoordinator`；保留查询语法、排序、清空查询、回到当前节点及切页恢复。
- 单击/方向键仅浏览；双击、Return、“使用”保持现有启用语义，自动选择组不能冒充手动组。
- 批量测速在操作行显示进度与取消入口；单节点只更新对应结果，不让整个列表反复重排或执行弹簧动画。
- 保留 provider 管理、自定义测速 URL、失败详情、固定菜单栏组和切换后关闭旧连接等现有入口。

### 配置

- 以原生 `Table` 为主：名称、来源、更新状态、可用时的流量/到期信息。当前配置用明确标记；不把列表铺成大卡片。
- 右侧详情聚合更新策略、使用情况、预检摘要与常用动作；窄窗口从“详情”打开 Sheet。
- 操作行提供添加菜单、更新、更多；添加菜单保留订阅、本地 YAML、手动代理、客户端迁移。拖入 YAML 进入导入确认流程，不直接启用。
- 编辑 Sheet 把基本信息、订阅选项、出站入口与高级覆盖分组；保留重置远程名称、回退选项、预检/审计及现有 Provider Details 入口。
- 当前配置切换、删除、应用与更新失败继续使用既有安全与确认逻辑；订阅 URL 默认遮蔽，公开预览全部使用虚构数据。

### 连接

- 保留“活跃/历史”、按应用分组、多选关闭与快速规则。搜索、筛选、选中项操作集中在同一页面操作区域。
- 表格优先展示应用、目标、规则/代理链、上下行；端口和其他诊断字段在检查器。排序和列宽尽量记住用户选择，数据刷新不能清掉仍有效的选中行。
- 双击打开详情；宽屏右侧检查器，窄屏 Sheet。多选时显示选中数量与批量动作，不能展示某一条的详情却对多条执行动作。
- “关闭连接”影响网络，始终明确作用于哪些连接；保留正在关闭的禁用状态。嗅探修复和规则创建必须仍由明确操作触发。

### 路由

- 保留片段库、编辑器、工具三块。工具区继续提供生效配置的层级/Diff/最终 YAML、诊断和匹配模拟。
- 使用 SwiftUIX `TextView` 评估替换当前普通多行编辑区，改善选择、撤销和输入法体验；结构化规则、DNS、嗅探等继续用原生表单。
- 草稿、已保存、待应用、应用失败必须分开表达。现有保存/应用流程与离开未保存草稿的处理保持有效。
- 诊断继续覆盖 DNS 覆盖、DNS 解析、Fake IP、监听与 Geo 数据库。最终 YAML、差异和复制输出沿用现有脱敏策略。

### 规则

- 保留有顺序语义的原生表格和现有查询能力。来源/Provider、匹配类型、内容、目标策略保持易扫描。
- 默认保持实际匹配顺序，不用视觉排序暗示运行规则已重排。筛选只改变展示，界面说明当前结果范围。
- 完整长规则进入详情或可复制文本；Provider 与搜索帮助继续按需打开。

### 日志

- 保留虚拟化列表与级别筛选，统一时间、级别、正文对齐；普通行紧凑，选中后读完整消息。
- 补充本地文本搜索和“跟随最新/暂停显示”。暂停只暂停视图追随/展示更新，不能停止日志采集；恢复时回到最新并保留既有存储上限。
- 阅读旧日志时不强制滚回底部；显示新增数量或“回到最新”入口。复制消息、复制整行继续保留。
- Debug 为空时保留“未开启 Debug 采集”的解释，不能显示成服务故障；错误正文保持稳定，不对每条流入执行动画。

### 状态

- 保留独立入口，成为运行事实与恢复操作的集中位置。顶部是当前概况，下方优先出现待处理问题。
- Runtime、DNS、规则覆盖、Helper、TUN、NE 继续按相关性分组；健康且无关的项默认折叠，问题项带具体原因与对应恢复按钮。
- 保留刷新、复制脱敏报告、诊断包预览/导出。显示用户实际需要判断的权限与运行所有者，不能以“异常”二字代替缺失的系统批准。

### 设置

同一设置内容服务主窗口入口和系统 `Settings` 场景，保留 `⌘,`。新增左侧分类与局部搜索；主窗口中可用窄分类列，独立设置窗口按自身宽度安排。

| 分类 | 现有内容归属 |
| --- | --- |
| 通用 | 外观、语言、启动、Dock/菜单栏、菜单栏流量显示 |
| 快捷键 | 继续使用 KeyboardShortcuts 的录制控件与冲突检查 |
| 运行与网络 | 核心运行选项、端口、控制器及网络策略等现有设置 |
| 订阅与规则 | 更新策略、订阅选项、规则覆盖、Geo 数据库 |
| 系统集成 | Helper、TUN、NE 的安装、批准状态、修复与高级设置 |
| 维护 | 备份恢复、更新、版本及现有相关信息 |

各分类使用 `Form(.grouped)`。搜索结果列出“设置项 + 所属分类”，点击定位而非复制第二份可编辑字段。保留当前设置的即时/保存后/重启后生效语义，并在需要时明确显示。

### 菜单栏

保持 320 pt 和系统面板背景。顺序为：当前状态与配置 → 启停主动作 → 流量 → 接管方式/运行模式 → 配置和常用代理组 → 次要动作。

- 保留固定代理组和更多代理组入口，节点名称在控件内截断，完整名称可查看。
- 更新当前订阅、更新全部、全组测速、检查更新、打开主窗口、退出等现有动作全部可达；次要动作可放菜单，避免多排相同权重的按钮。
- 系统代理开关的可用条件继续严格匹配接管方式；停用原因可见。
- 主窗口关闭后的常驻、静默启动和 Dock 策略保持现有行为；不引入 SwiftUIX WindowOverlay 接管系统菜单栏窗口。

## 6. SwiftUIX 与原生交互补齐

已静态核对 SwiftUIX 源码修订 `3a99044b7045fb5907a7df18c7fe323e5656c6ab`。包声明支持 macOS 11+；这不等于已在 ClashMax 的 Swift 6 构建或中文输入场景通过验证。

| 交互 | 实现选择 | 具体范围与验证 |
| --- | --- | --- |
| 页面内嵌搜索 | SwiftUIX `SearchBar` 的 `NSSearchField` 实现 | 连接、规则现有内嵌搜索及新增日志/设置搜索；系统清除按钮、焦点环和输入法。代理页已有 `.searchable` 继续使用 |
| 多行编辑 | SwiftUIX `TextView` 的 AppKit 实现 | 路由片段与适合的配置多行输入；源码已有 `allowsUndo`、`editable`、`isSelectable`，仍需测中文组合输入、撤销重做、光标、粘贴与大文本 |
| 检查器 | SwiftUI `.inspector`、`InspectorCommands` | 配置、连接等详情；框架已有能力，不由 SwiftUIX 重造 |
| 列表/表格 | SwiftUI `List` / `Table` | 多选、上下键、双击、上下文菜单、列宽与排序；补齐命令路由和状态保持 |
| 文件拖入/导入导出 | 系统拖放 API、打开/保存面板 | YAML 拖入走现有导入和校验；拖放只是入口，不绕过校验或启用确认 |
| 窗口与菜单栏 | 现有 Scene/AppDelegate 与系统 `MenuBarExtra` | 保持恢复、激活、静默启动、Dock 行为；不新增全屏顶置窗口 |

**已发现的 SwiftUIX 限制**：本次修订的 `SearchBar.updateNSView` 会设置焦点绑定，却没有看到根据绑定主动调用 `makeFirstResponder` 的路径。因此不能把 `.focused(...)` 等同于 macOS `⌘F` 已完成；也不能承诺 iOS 风格 search tokens 在 Mac 自动可用。先在独立原生原型中验证，焦点缺口由最小 AppKit 适配解决，或该处沿用系统 `.searchable`。其他确认有效的 SwiftUIX 控件照常推进。

只在相关叶子组件导入 SwiftUIX，使用限定名避免与本地 `TextView` 等命名混淆。依赖选择可复现版本/修订；实施前重新核对可用发行版与构建结果。本方案只提出新增 SwiftUIX，其余候选包不预先安装。

### 键盘与指针约定

- 保留 `⌘R` 启停、`⌘0` 打开主窗口、`⌥⌘1/2/3` 切运行模式、`⌥⌘S` 系统代理、`⌥⌘P` 配置入口、路由编辑的 `⌘S` 保存及用户配置的全局快捷键。
- `⌘F` 聚焦当前页面搜索；表单输入时不拦截系统编辑快捷键。`⌘C/A/Z/⇧Z` 根据当前第一响应者作用于文本或选中行。
- Return 在节点列表中延续明确启用行为；其他列表按既有主动作处理，不将统一快捷键扩展成隐式配置切换。
- Escape 先关闭当前弹层/取消局部操作，再返回触发控件；不直接停止网络。删除只在有明确选中对象且焦点不在输入框时处理，沿用确认流程。
- 所有图标操作有 tooltip、可访问名称和键盘入口。悬停只改变强调度，不改变行高、宽度或选择。
- 检查器使用系统命令及快捷键；新增命令前核对本地菜单、文本编辑器和用户全局快捷键冲突。

## 7. 动效分工

| 事件 | 效果 | 原型起始参数 |
| --- | --- | --- |
| 系统按钮、菜单、切换控件 | 系统原生交互与 Liquid Glass | 不叠加 Pow 按压缩放 |
| 当前节点成功切换 | 勾号/状态符号短促反馈；适合时使用已有 Pow change effect | 180–240 ms，单次 |
| 首页启动前后 | 保留位置的交叉淡入和小范围尺寸过渡 | 180–250 ms，无大幅弹跳 |
| 自定义快捷玻璃控件展开 | 同一容器内稳定 ID 的原生玻璃形变 | 200–280 ms，26+ |
| Toast 出入 | 沿用现有顶部反馈，短距离淡入淡出 | 约 160–220 ms |
| 真实加载 | 共用 Shimmer 骨架或原生进度 | 不替换失败、停止或恢复状态 |
| 流量数字、节点延迟、日志流入 | 局部更新，固定宽度；高频更新不执行整页动画 | 按现有数据节奏 |

Reduce Motion 使用无位移淡入或立即切换，去掉弹性、形变与循环效果。后台/不可见区域停止仅为视觉服务的持续动画，网络业务采集按现有规则运行。动画成功反馈必须等待实际操作成功，不能在点击时提前宣布成功。

## 8. 状态与反馈合同

| 状态 | 必须看到的内容 | 可用动作 |
| --- | --- | --- |
| 无配置 | 无配置及其后果，首个导入入口 | 添加订阅/导入 YAML |
| 缺少内置核心 | 明确核心不可用 | 既有恢复指引/查看详情；启动不可用 |
| 已停止且就绪 | 当前配置、计划接管方式；没有伪实时流量 | 启动、编辑、已有离线节点选择 |
| 预览运行时 | 仅为预览/测速，尚未接管系统流量 | 既有测速/选择与正式启动 |
| 启动/重启中 | 真实阶段与进度，避免连续提交 | 仅在已有安全停止路径时允许停止 |
| 核心运行但未接管 | 核心运行事实与接管状态分别显示 | 明确的接管动作或诊断 |
| 系统代理/TUN/NE 正在接管 | 实际所有者、实际模式、最新有效数据 | 停止、切换及相关运行操作 |
| Helper/NE 未就绪 | 缺的是安装、签名、系统批准还是运行条件 | 对应安装/打开系统设置/修复 |
| 崩溃或部分恢复失败 | 失败原因及残留代理/DNS 等已知事实 | 查看日志、恢复；仍可清理时提供停止 |
| 更新/校验/应用失败 | 哪个对象失败、当前运行状态是否受影响 | 详情、重试、已有回退；不丢草稿 |
| 搜索无结果/真实空集合 | 区分过滤结果与没有数据 | 清除筛选或对应下一步 |
| 数据陈旧/请求失败 | 最近有效值与更新时间/失败标记 | 重试；不把旧值显示成新成功 |

成功通知可短暂显示；错误继续使用现有原生 Alert 及可追溯详情。涉及恢复的持续问题留在状态行/状态页，不因 Toast 消失而丢失。状态映射复用 `DashboardRuntimeState`、`MenuBarRuntimePresentation` 等现有来源，不在各页面重新发明运行状态。

## 9. 组件与代码落点

- **复用并演进**：`ContentView`、`SidebarView`、`AdaptivePage`、`StatusStripContent`、`PageStatusFooter`、`CenteredUnavailableState`、`SurfaceRadius`、共用 Shimmer、`AppNoticeToast`。
- **首页**：`DashboardView`、`RunningDashboardView`、`LaunchDashboardView`、`CoreVisualView`、`PublicIPInfoCard` 与已有流量组件。保留后台解析、异步加载和运行状态所有权。
- **数据页面**：各页保留数据模型/协调器；先统一布局和选择/详情行为，再处理搜索与文本输入适配，不把 UI 改造扩大成 Store 重构。
- **按实际复用新增少量叶子组件**：嵌入式搜索输入、片段文本编辑器、共用详情内容。只有两处以上有相同职责时才抽取；不创建通用主题引擎或新的导航框架。
- **依赖与资源**：实施时在 `project.yml` 为 App target 添加 SwiftUIX，并更新第三方声明；不添加到 Helper/NE。保留签名、证书、entitlements、App Group 与现有其他依赖。
- **可选组件**：PopupView 暂无必要，已有 Toast/Sheet/Popover 可复用；Glur 仅在真实原型证明需要自绘渐进模糊时再评估主模块，排除 GlurBackdrop；Inferno 不进入首轮，避免把高频网络界面变成持续 shader 展示。

### 验证与交付

- 每阶段先跑受影响的窄检查。已有可复用测试包括 `DashboardRuntimeStateTests`、`ProxySearchPipelineTests`、`MenuBarRuntimePresentationTests`、`MenuBarPanelLayoutTests`、`MainWindowLayoutTests`、`PageOverflowLayoutTests`、`GlobalShortcutSettingsTests`、`LocalizationTests`；改变连接详情布局时同步更新表达旧堆叠行为的测试。

- 原生视觉验证覆盖浅/深色、English/简体中文、最小/默认/宽窗口、长配置名与长错误、键盘全程、VoiceOver、减少动态效果、减少透明度、提高对比度。

- 涉及真实系统代理、TUN/NE、DNS、路由的联动测试，在覆盖该操作的授权下进行，记录并恢复基线；纯视觉阶段不需要这些操作。
