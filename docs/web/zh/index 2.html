第一屏就是代理客户端。

启动、停止、切换模式、检查 TUN/helper ready 状态，并在系统代理异常时给出恢复路径。

原始 profile 保持不动，运行态配置由应用托管。

ClashMax 保留原始 YAML，在启动前生成 runtime YAML，用来写入端口、controller auth、DNS、TUN 和运行模式。

配置来源

订阅和本地 YAML 保持可读、可恢复，并与启动时注入的配置分开。

app 里有八个界面。

Dashboard、配置、代理、连接、规则、日志、设置，以及 macOS 菜单栏。

  • Dashboard

    启动、停止、切换模式，检查 TUN/helper ready 状态

  • 配置

    本地文件和订阅 URL 有清晰归属，也有明确更新路径

  • 代理

    切换代理组、执行延迟测试，读取 provider 健康状态

  • 连接

    查看会话、目标地址、规则命中、上传与下载

  • 规则

    看清流量为什么直连、代理或拒绝，不必先打开原始配置

  • 日志

    Mihomo 日志靠近运行控制，便于排查配置和网络问题

  • 设置

    端口、DNS、TUN、开机启动、更新

  • 菜单栏

    从 macOS 菜单栏查看状态并执行快速控制

代理组快速可扫，流量可检查。

这两块是照 app 自己的布局、文案和状态用 HTML 重画的，缩放到任何尺寸都还看得清。

安全敏感行为不说空话。

代理客户端会触碰本机网络设置，所以页面也写清应用实际执行的边界。

  • 本地控制面

    Mihomo controller 默认绑定 127.0.0.1，并使用 Bearer auth 保护访问。

  • 每次启动密钥

    每次启动生成新的 controller secret，避免依赖共享静态凭据。

  • Helper 边界

    用户态负责普通系统代理；privileged helper 负责 TUN，并校验 app-owned core/config paths。

  • 只跑内置内核

    只运行内置的 Mihomo 内核。要开新的内核通道，得先有清单、哈希校验和 helper 白名单。

  • Keychain 凭据

    订阅链接按配置 ID 存进 Keychain，不会写进运行时 YAML。

  • GPL-3.0 边界

    ClashMax 分发并控制 Mihomo，因此保持 GPL-3.0 兼容的许可边界。

安装分四步。

从 release 页面到内核跑起来。

  1. 下载 DMG

    从最新 release 里取 ClashMax-X.Y.Z.dmg。

  2. 拖进 Applications

    必须装到 /Applications，helper 授权和实验性的 Network Extension 都依赖这个位置。

  3. 导入配置

    打开本地 Clash / Mihomo YAML 文件，或添加订阅，然后在 Dashboard 启动运行时。

  4. 同意系统弹窗

    TUN 模式和 NE Proxy 各自需要对应的 macOS 授权才能跑。系统代理模式不需要。
